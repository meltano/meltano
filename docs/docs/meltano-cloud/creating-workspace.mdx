# Workspaces

A **workspace** is your isolated data environment in Meltano: a dedicated project for a team, a client or a use case. Each workspace has its own ingestions, workflows, warehouses and configuration, all backed by a Git repository.

You can be a member of several workspaces, and each one operates independently. Switch between them with the **workspace menu** at the top of the page.

---

## Your first workspace

When you sign in for the first time, the setup wizard creates your first workspace. See [Onboarding](/meltano-cloud/onboarding).

---

## Create another workspace

1. Open the **workspace menu** at the top of the page.
2. Click **New Workspace** (first in the list). It opens the same setup wizard, titled **New Workspace**, with a **Cancel** to go back.
3. Follow the steps: name the workspace, then choose its warehouse and sources.

The new workspace goes in your **working account** (see [Personal Settings](/meltano-cloud/personal-settings#account)). If you can't create one, for example because the account has as many workspaces as it is allowed, **New Workspace** is greyed out and says why.

---

## From an existing repository

If you already have a Meltano project in a Git repository, or a workspace created earlier in Matatika, you can deploy it as a workspace.

1. On the wizard's first step, open **Additional Options** ("Deploy an existing workspace or Meltano project from Git").
2. Fill in:
   - **URL** of the repository.
   - **Branch** to deploy.
   - **Repository Directory (Optional)**: the folder that holds the project, if it isn't the repository's root.
   - **SSH Private Key**: for a private repository reached by an SSH URL.
   - **Github Installation ID**: for a repository reached through the Meltano Cloud GitHub App.
   - **Meltano Version**.
3. Continue. The wizard skips the warehouse and sources: they come from the repository.

Meltano deploys the workspace from that repository: its warehouses, connectors, ingestions and workflows are read from it. Meltano never pushes changes back to a repository you bring, and never renames or deletes it. To change the workspace, push to the repository and deploy (see [Managing a Workspace](/meltano-cloud/managing-a-workspace#managing-config-from-github)).

:::tip Supported repositories
This works with any repository created by Matatika or any existing Meltano project.
:::

## Manage your workspace

| Surface | Best for |
|---|---|
| **Meltano Cloud** (the app) | Day-to-day work: ingestions, workflows, warehouses, plugins, team |
| **Meltano API** | Programmatic access, automation, CI/CD integrations |
| **Your own machine** | Running pipelines locally, editing the project's files directly |

- **Settings** in the sidebar holds the workspace's name, approved domains, repository and integrations. See [Workspace Settings](/meltano-cloud/workspace-settings).
- To run an ingestion on your own machine, see [Ingestion](/meltano-cloud/ingestion#run-an-ingestion-on-your-own-machine).

## Workspace concepts

| Concept | What it means |
|---|---|
| **Git-backed config** | The workspace's configuration is a Meltano project in a single Git repository. In a repository Meltano created, changes made in the app are committed to it. |
| **Isolated warehouse** | Each workspace loads into its own warehouses (PostgreSQL, Snowflake, BigQuery, Microsoft SQL Server, ClickHouse, MotherDuck or Databricks) and cannot access another workspace's data. |
| **Roles** | In a workspace, people are an **Administrator** or a **Member**. The account's owners manage every workspace in the account. See [Team](/meltano-cloud/team). |
| **Approved Domains** | Optionally restrict who can be invited by email domain. |

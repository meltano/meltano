# Workspace Settings

Open **Settings** in the sidebar. The page has four tabs, and a **Deploy** button at the top right of each. Only the workspace's administrators can change settings; a member sees them read-only.

---

## General

- **Name**: the name members see everywhere. Renaming the workspace also renames its repository, which may break automation that uses the old name.
- **Approved domains**: only people with an email address in these domains can be invited. Leave it empty to allow any domain.
- **Active environment**: the [Meltano environment](/concepts/environments) whose configuration the workspace uses. It must exist in `meltano.yml`. See [Managing a Workspace](/meltano-cloud/managing-a-workspace#managing-config-with-environments).
- **Meltano version**: the version of Meltano the workspace runs on.
- **Logo**: an image (cropped when you add it) that helps members see they are in the right workspace. **Remove Logo** takes it away.
- **Danger Zone → Delete Workspace**: removes the workspace for everyone in it. You type the workspace's name to confirm. This can't be undone.

Click **Save** to keep your changes. Changing the active environment or the Meltano version asks you to type the workspace's name first, because the next runs of every ingestion and workflow use the new one.

---

## Repository

Where the workspace's Meltano project lives, and how changes reach Meltano Cloud.

- **Repository URL**, **Branch** and **Directory** (the folder in the repository that holds the project; empty for the repository's root). Copy them from here to clone the repository.
- **GitHub installation ID**: the Meltano Cloud GitHub App installation that gives access to the repository.
- **SSH private key**: for a private repository reached by an SSH URL. A saved key is never shown again: type a new one to replace it, then Save.
- **Deployment secret**: the secret GitHub signs its webhook calls with, so that a push to the repository deploys the workspace. Copy it, or **Regenerate Secret** to replace it; the old one stops working, so update the webhook in GitHub too. See [Managing a Workspace](/meltano-cloud/managing-a-workspace#managing-config-from-github).

---

## Integrations

Services the workspace connects to. Only administrators see this tab. A credential is tested before it is kept, and kept when you click **Save**.

- **Claude**: an Anthropic API key, so that Meltano AI can diagnose failed runs. Click **Add Credential** and paste the key. It is saved masked and can't be seen again. **Remove** takes it away at once, and AI diagnosis stops until a new key is added. See [Diagnose with Meltano AI](/meltano-cloud/diagnose-with-meltano-ai).
- **Datadog**: an API key and site, so that the logs of your ingestions and workflows are sent to Datadog. Pause it to stop sending without removing the credential. See [Log Routing and Monitoring](/meltano-cloud/logging-monitoring).

---

## Deployment History

Every deployment of the workspace, with its status, when it started, how long it took, the **Commit** it deployed (linked to the repository) and who or what **Triggered By** it. For each one you can **View Log** or delete it from the history. A failed deployment also has **Diagnose with Meltano AI** and **Copy Diagnosis Prompt**.

---

## Deploy

**Deploy**, at the top right of every Settings tab, applies what is in the repository to the workspace now, without waiting for a push. Follow it in **Deployment History**.
